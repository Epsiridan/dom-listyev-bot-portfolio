# Портфолио: бот «Дом Листьев»

Снимок исходного кода без истории Git и рабочих данных. Контакты администраторов обобщены; ID в примерах вымышлены. Перед запуском задайте собственные переменные окружения, включая обязательный `ADMIN_GROUP_ID`. Архив не содержит базу данных, логи или ключи доступа.

# Дом Листьев Bot

Telegram-бот для сообщества «Дом Листьев»: вход в закрытую группу через правила, предложка творческих публикаций, конкурсные заявки, мероприятия и админские инструменты.

## Что умеет бот

### Для участников

- показывает главное меню по `/start`;
- выдаёт правила сообщества и создаёт персональную одноразовую invite-ссылку в группу;
- принимает посты в предложку канала «Дом Листьев»;
- показывает в главном меню активные конкурсы и принимает работы по их настройкам;
- показывает мероприятия Дома Листьев и позволяет записаться вплоть до 30-й минуты после начала или отменить запись;
- описывает изображения для незрячих и слабовидящих участников по команде `/опознай` или `/опознай@DomListyevBot`;
- поддерживает игровые команды `/исследуй ...` и `/исследовать комнату ...` в группе.

### Для администраторов

- показывает скрытый от обычных участников раздел `🛡 Администрация` в личке;
- отправляет предложенные посты в админский чат на модерацию;
- позволяет одобрить лист в очередь, опубликовать сразу, отредактировать или отклонить;
- автоматически публикует одобренную очередь в канал по расписанию;
- показывает очередь публикаций и умеет удалять листы со сдвигом следующих слотов;
- помогает создавать и администрировать мероприятия;
- рассылает напоминания за выбранное администратором количество часов и, по желанию, дополнительно за 15 минут;
- сразу отправляет ссылку участнику, который записался менее чем за 15 минут до начала или в первые 30 минут встречи;
- создаёт конкурсы через кнопочный конструктор и передаёт заявки в выбранную группу/топик;
- даёт диагностические команды для Telegram ID, chat_id и message_thread_id;
- позволяет менять базовые тексты и изображения через `🛡 Администрация` → `🎨 Тексты и оформление`;
- подтверждает изменение существующих значений экраном `Было → Станет`, не записывая черновик до кнопки `Сохранить`.

## Быстрый старт локально

1. Создайте и активируйте виртуальное окружение:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

2. Установите зависимости:

```powershell
pip install -r requirements.txt
```

3. Скопируйте `config.example.yaml` в `config.yaml` и задайте там несекретные ID/настройки. `config.yaml` исключён из Git.

4. Задайте `BOT_TOKEN` через окружение. При желании остальные параметры также задавайте по `.env.example`.

5. Запустите бота:

```powershell
python bot.py
```

> В проекте нет встроенного загрузчика `.env`. Для локального запуска задайте переменные через PowerShell/терминал, IDE или добавьте загрузчик отдельно.

## Приоритет конфигурации и безопасность

Настройки читаются в порядке **ENV → `config.yaml` → встроенное значение**. Путь к файлу можно изменить через `CONFIG_FILE`. ID администраторов, групп, каналов и топиков, часовой пояс и расписание разрешено хранить в локальном YAML.

`BOT_TOKEN` и `OPENAI_API_KEY` намеренно читаются **только из ENV**. Не помещайте токены, пароли и API-ключи в `config.yaml`, SQLite, документацию или Git. `content.defaults.yaml` содержит только публичный контент.

Railway полностью совместим с прежней схемой: если все значения заданы Railway Variables, `config.yaml` не нужен.

## Права бота в Telegram

Для корректной работы бот должен иметь достаточные права:

- в основной группе `GENERAL_GROUP_ID`: видеть сообщения, проверять участников, создавать invite-ссылки;
- в канале публикаций `PUBLIC_CHANNEL_ID`: публиковать сообщения и медиа;
- в каналах, где проверяется подписка: быть **администратором**, чтобы Telegram позволял надёжно вызывать `getChatMember`;
- в админском чате `ADMIN_GROUP_ID`: отправлять сообщения в нужные топики;
- для группового сценария `@DomListyevBot новый лист`: читать сообщения в группе и топике-источнике.

## Основные сценарии

Подробная инструкция для участников и администраторов находится в [`docs/USAGE.md`](docs/USAGE.md).

Коротко:

- `/start` — открыть главное меню;
- `/cancel` — отменить текущий сценарий и вернуться в меню;
- `/my_id` — узнать свой Telegram ID;
- `/topic_id` — узнать ID чата и топика в группе/канале;
- `@DomListyevBot id` — быстрый вывод chat_id и thread_id в группе;
- `@DomListyevBot новый лист` — отправить пост из топика «Проза и поэзия» в предложку;
- `/опознай` или `/опознай@DomListyevBot` — описать приложенное изображение или изображение в сообщении, на которое дан ответ;
- `/исследуй Архив №7` (также `/исследуй комнату Архив №7` и `/исследовать комнату Архив №7`) — исследовать пространство, следы и отклик Дома;
- `мой журнал` — скрыто показать личный список исследованных комнат.

### Одноразовый разговор со Смотрителем

Администратор может незаметно взвести пасхалку точной фразой `смотритель, проснись`.
Следующая корректная команда `/исследовать комнату ...` в основной группе вместо
обычного отчёта начинает разговор со Смотрителем. Участники продолжают его прямым
ответом на последнюю реплику бота.

Первая необычная реплика считается ответом №1. Ответ №10 всегда является строгим
завершением: Смотритель сообщает, что должен продолжать обход и что разговор окончен.
Если десятый ответ не наступил, через три часа после начала бот сам отправляет тот же
финал в исходный чат или топик. Перезапуск не сбрасывает таймер: состояние хранится в
SQLite.

Новые текстовые сообщения основной группы сохраняются только в локальной базе, не
передаются во внешнюю AI-модель и ограничены последними 2000 сообщениями. Telegram Bot
API не позволяет задним числом получить старую историю группы.

## База данных

Бот использует SQLite-файл `submissions.db` в `DATA_DIR`. При старте `init_db()` создаёт таблицы и применяет совместимые миграции:

- `submissions` — старая история заявок «ЭХО», которая мигрирует в новую модель;
- `contests` — настройки, сроки и статусы конкурсов;
- `contest_required_channels` — каналы для обязательной подписки;
- `contest_submissions` — заявки с привязкой к конкретному конкурсу;
- `room_explorations` — глобальные кулдауны исследований;
- `room_exploration_history` — полная история трёх аспектов и 48-часовых последствий.
- `keeper_easter_egg` — одноразовое взведение пасхалки;
- `keeper_group_messages` — локальная ограниченная память новых сообщений группы;
- `keeper_dialogues` — активные и завершённые разговоры со Смотрителем;
- `proposed_posts` — предложенные листы и очередь публикаций;
- `maintenance_tasks` — служебные отметки;
- `house_events` — мероприятия;
- `house_event_registrations` — записи участников на мероприятия;
- `bot_content` — админские переопределения текста, Telegram `file_id`, режим отправки, `updated_at` и `updated_by`.

Стандартные значения остаются в `content.defaults.yaml`. Чтение идёт по цепочке: **SQLite → стандартный файл → аварийный fallback в коде**. Сброс блока удаляет только переопределение и возвращает стандартное значение.

На Railway для `DATA_DIR` желательно использовать persistent volume, иначе очередь и история могут потеряться после redeploy.

## Деплой

Текущий ожидаемый путь деплоя — Railway.

1. В Railway задайте Variables из `.env.example`; существующие имена переменных сохранены.
2. Для данных настройте persistent volume и укажите `DATA_DIR` на путь volume.
3. Запуск: `python bot.py`.
4. После `git push` Railway автоматически пересобирает и перезапускает сервис.

## Админские команды

Основные админские действия доступны кнопками: `/start` → `🛡 Администрация`.
Команды, требующие администратора, дополнительно проверяют `ADMIN_IDS`.

| Команда | Где | Назначение |
| --- | --- | --- |
| `/my_id` | личка/чат | показать Telegram ID пользователя |
| `/topic_id` | группа/канал | показать `chat_id`, `message_thread_id`, `chat_type` |
| `/reset_my_submission` | личка/чат | удалить тестовую конкурсную заявку текущего админа |
| `/delete_submission @username` или `/delete_submission 123` | личка/чат | удалить конкурсную заявку пользователя |
| `/clear_submissions` | личка/чат | полностью очистить историю конкурсных заявок |
| `/cleanup_published 30/60/90` | личка/чат | удалить опубликованные листы старше выбранного срока |

## Разработка

- Секреты не хранить в коде и Git.
- Новые пользовательские тексты по возможности выносить в `texts.py`.
- Новые кнопки — в соответствующем файле `keyboards_parts/`; `keyboards.py` оставляйте совместимым фасадом.
- Бизнес-логику держать в `services/`, обработчики — в `handlers/`.
- При изменении БД обновлять `services/database_schema.py`, чтобы старые Railway-базы не ломались.
- Не коммитить `data/`, `*.db`, `.env`, токены и выгрузки.
- Перед изменением сценария смотреть карту в [`docs/EDITING_GUIDE.md`](docs/EDITING_GUIDE.md).
- Проверять чистые функции командой `python -m unittest discover -s tests -v`.
